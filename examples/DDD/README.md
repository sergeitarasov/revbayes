# Using the diversity-dependent likelihood in RevBayes

Run from the **nested RevBayes repository root** (`rb-fbdp/revbayes`):

```sh
.local-build/revbayes-build/rb examples/DDD/likelihood.Rev
```

This requires the development binary built in this checkout. `fnDiversityDependentLogLikelihood` is not assumed to exist in a released RevBayes installation. If your binary is elsewhere, replace the executable path.

The script reads the supplied six-tip extant tree, evaluates its likelihood, checks a larger hidden-lineage cutoff, demonstrates three rate laws, and writes a likelihood profile to `examples/DDD/output/profile.tsv`. The expected power-law log likelihood is **-7.9263828301537**. The grid maximum is lambda0=4.3, close to the continuous optimum 4.271567, with mu=0.2 and K=8 fixed. This estimate is from one small simulated tree; it is not the generating value (lambda0=0.8).

For an independent comparison in R:

```sh
Rscript examples/DDD/compare_in_R.R
```

The R script requires installed `DDD` and `ape`. It checks the same likelihood and, if present, the Rev-generated profile. The six-tip teaching tree was generated by DDD 5.2.5 with seed 1439, model 2, lambda0=0.8, mu=0.2, K=8, and crown age 3. The larger simulation study in `validation/DDD_presentation` instead uses **K=15**.

## Use your own tree

Change the input path, and remove or update the example-specific assertion against -7.92638283015368. The input must be rooted and binary, with branch lengths in time units, all tips at the present, and all living species sampled. No fossils or character matrix enter this function.

```rev
tree = readTrees("my_tree.tre")[1]
lnL := fnDiversityDependentLogLikelihood(tree, lambda0=0.8, mu=0.2,
           K=15, rateModel="DDDpower", start="crown", condition="survival",
           maxHiddenLineages=128, numericalTolerance=1e-13)
print(lnL)
```

- `DDDpower` matches DDD model 2: lambda(N)=lambda0*(N+1)^[-log(lambda0/mu)/log(K+1)].
- `DDDlinear` matches DDD model 1: max(0,lambda0-(lambda0-mu)*N/K).
- `exponential` uses lambda(N)=lambda0*exp[-alpha*(N-1)]. Supply `alpha`; this is a different model from DDD model 2.
- N includes hidden living lineages, not just reconstructed branches. Mu is constant.
- For DDD rate laws the current interface requires lambda0 > mu > 0 and K > 0.
- `start="crown"` uses the tree's root age and conditions on two starting lineages. A stem analysis uses `start="stem", originAge=...` with age at least as old as the root.
- `condition="survival"` matches DDD `cond=1`; `none` and `nTaxa` match `cond=0` and `2`.
- The default `density="DDDphylogeny"` matches `btorph=1`. `branchingTimes` matches `btorph=0` and adds log((n-1)!).
- Increase the hidden-lineage limit until the likelihood converges. Reducing numerical tolerance alone cannot remove truncation error.

This is a deterministic likelihood evaluation function. It is not a stochastic tree distribution, and including its return value in `model(...)` does not by itself create an MCMC likelihood factor. The example deliberately demonstrates evaluation and a fixed-tree likelihood profile.
