## Best starting point

`src/core/distributions/phylogenetics/tree/birthdeath/OccurrenceBirthDeathProcess.{h,cpp}` already wraps a joint reconstructed tree plus anonymous occurrence likelihood, including a hidden-lineage cutoff. This is substantially closer than patching ordinary FBD branchwise formulas. Header lines 16–20 distinguish phylogenetic fossil sampling psi from unplaced occurrence sampling omega; constructor 51–163 builds parameters; computeLnProbabilityTimes cpp:196–215 delegates to `ComputeLnLikelihoodOBDP`.

`src/core/functions/phylogenetics/ComputeLikelihoodsLtMt.{h,cpp}` is the crucial existing algorithm. It pools tree/occurrence events (cpp:34–125), computes oldest-to-youngest hidden-state vectors (308–541), and implements a backward counterpart (562 onward). There is no ODE class on the forward path: cpp:420–429 materializes a dense matrix and calls `RbMath::expMatrixPade(A,A,4)` then multiplies the state vector. The state uses k reconstructed lineages plus i hidden lineages. Its off-diagonal hidden births are lambda*(2k+i-1), not lambda*(k+i-1), because a branching of a reconstructed lineage has two orientations for the continuing reconstructed child.

For forward elapsed time s, adapt the existing fixed-k generator to
A[i,i]=-(k+i)*(lambda(k+i)+mu+psi+omega),
A[i,i+1]=mu*(i+1),
A[i,i-1]=lambda(k+i-1)*(2k+i-1).
The state is an unnormalized tree-observation density, so this is a substochastic/Feynman–Kac operator in a particular tree measure, not the ordinary demographic generator. A derivation and constant-rate cross-check must fix the convention before implementation.

At a reconstructed branching event, existing cpp:486–489 increments k and puts scalar log(lambda) into a global accumulator. DD must multiply each state by lambda(k+i) BEFORE k increments. Simply substituting a scalar rate calculated from the reconstructed tree is incorrect. Fossil leaf (459–467), sampled ancestor (469–474), and occurrence (477–483) transitions offer reusable formulas. For non-removing samples r=0: a fossil leaf shifts hidden count up by one while reducing k by one; SA multiplies by psi with no change in N; an anonymous occurrence multiplies by omega*(k+i). Present weighting cpp:527–533 is rho^k*(1-rho)^i.

## Critical normalization and modeling traps

1. `AbstractRootedTreeDistribution.cpp:266–268` automatically adds `lnProbTreeShape` to the subclass time density. The inherited default at 468–476 is `(tips-1)log2 - 2 log(tips!) + log(tips)`. OBDP does not override it. Ordinary FBD `BirthDeathSamplingTreatmentProcess.cpp:832–844` DOES override it with `(tips-sampledAncestors-1)log2 - log(tips!)`. DD needs an explicit, derived shape correction. Never trust the OBDP default merely because its hidden recursion is useful. FBD-vs-DD alpha=0 comparisons must test both ordinary tip trees and differing sampled-ancestor counts; constants can affect topology/SA posterior odds.
2. `AbstractBirthDeathProcess.cpp:49–80` conditions survival by squaring one-lineage survival. DD globally couples lineages, so this must not be inherited. OBDP overrides `computeLnProbabilityDivergenceTimes` at 185–190. Its own conditioning in `ComputeLikelihoodsLtMt.cpp:275–280` uses branching-independent functions `GetFunctionUandP`; those also cannot be reused for DD. Initially support origin conditioning and none, plus separately solved >=1 sampled extant conditioning. Crown conditioning requires its own definition and coupled state-space calculation, never a product of independent lineage survival.
3. OBDP `ComputeLnLikelihoodOBDP` cpp:228–238 has a special analytic all-removed shortcut; disallow this shortcut in DD. Its helper functions presume linear independent birth death.
4. OBDP `PoolEvents` labels true bifurcations only when neither child is a sampled-ancestor tip (98–101). An SA parent is an encoding artefact, not a birth. Sorts compare only age (330–332); implement deterministic same-time event batches/tie rules and handle root=origin carefully.
5. Do not inherit the `offset` logic blindly. Current OBDP computes tip-based offsets, but a genuine present with rho and fossil-only data must remain calendar age zero rather than shifting to most recent fossil.
6. OBDP tail warnings (496–519) are a heuristic max-vector threshold, not truncation error control. Include cemetery leakage/cutoff doubling and log-likelihood/parameter convergence. Keep boundary killing diagonal; reflecting by deleting upward exit changes the model.
7. Scaling at 491–495 divides by max without a zero check. DD needs robust impossible-state handling, negative probability tolerance, finite checks, and accumulated log scales.
8. OBDP header stores `cond` as a const string reference. New class should own immutable strings/config. Its constructor registers rates but not occurrence_ages or maxHiddenLin; new DD must register every stochastic dependency and swap corresponding TypedDagNode pointers. Do not copy omissions.

# Revision: repeated occurrences assigned to named species

The initial OBDP recommendation applies to anonymous occurrences. For the user's now-explicit named-species records, it is a numerical scaffold only, NOT the full observation model. The architecture must preserve species identities and repeated samples within a species.

## Existing named-species implementation

- `Taxon.h:16–17,39,47,62` and `Taxon.cpp:129–177`: each species stores `map<TimeInterval,size_t>` observations. Thus multiple observations, uncertainty intervals, and counts are represented, not only first/last ranges. Equal intervals aggregate counts; unique specimen/occurrence identifiers are not preserved by this type. Keep a separate occurrence table with occurrence_id, species_id, age constraints and character-data linkage if those identities matter.
- `AbstractFossilizedBirthDeathRangeProcess.cpp:173–184` extracts oldest-minimum and youngest-maximum constraints, while `:283–371` actually traverses all occurrence intervals and counts. The complete flag changes observation likelihood: `:353–364` uses the complete-count term or marginalizes additional unreported fossils. Therefore it is false to say this class only accepts first/last ranges.
- `FossilizedBirthDeathSpeciationProcess` inherits both tree and range bases (`.h:28`), so the distribution value is an extended `Tree`. `updateStartEndTimes(const TopologyNode&)` cpp:566–651 recursively maps tip indices to named species. At an ordinary bifurcation, child 0 retains the parent species identity; child c>0 begins a new species at that node's age. The root's continuing species starts at origin. Tips' ages are extinction times (cpp:585–600), NOT fossil observation times. Species identity therefore depends on child order, even if generic phylogenetic code would regard child rotations as equivalent.
- The process supports mixed budding/asymmetric, symmetric, and anagenetic speciation. Rev wrapper is `Dist_FBDSP.{h,cpp}`; parameter defaults cpp:202–207 give lambda_a=0 and beta=0. Beta is symmetric-speciation probability; lambda_a is anagenetic rate. A budding-only DD first version should explicitly fix both at zero and define lambda(N) as cladogenetic per-species birth rate.
- `q(tilde=true)` in Speciation cpp:218–253 and cached `q_tilde_i` in :658–689 account for identity persistence. The range base multiplies q/qtilde pieces around the oldest observation (`:245–276`). These analytic formulas use branching independence and cannot merely receive lambda evaluated at observed diversity.
- SA flags mean something different here: `I[i]` marks daughter descending from a sampled ancestor and `computeLnProbabilityTimes` :149–164 replaces birth+death factors by anagenetic rate. Do NOT indiscriminately reuse specimen-FBD sampled ancestor moves/interpretations in budding-only species trees. With lambda_a=0 those anagenetic configurations have zero probability.
- Explicit tree shape correction Speciation cpp:191–198 is `-log(n_extant!)`, for its stated labeled oriented measure. This differs from specimen FBD and must be derived rather than mixed across representations.
- `help/md/dnFossilizedBirthDeathSpeciation.md` documents full occurrence uncertainty, complete=FALSE, oldest-occurrence augmentation via mvResampleFBD, and tips representing extinction events.

## Serious current implementation limitation

`FossilizedBirthDeathSpeciationProcess.h:66` declares non-const `computeLnProbabilityDivergenceTimes(void)` with an inline comment `override fail. should be const.` Its definition cpp:129–136 calls the range likelihood. But the base virtual in `AbstractRootedTreeDistribution.h` is const and `AbstractBirthDeathProcess.cpp:49` implements the const overload. Normal virtual dispatch from `AbstractRootedTreeDistribution::computeLnProbability` therefore will not invoke this non-const derived method. This is a source-level finding, not a runtime-tested bug report. Existing FBDSP must not serve as an unquestioned numeric oracle until this is reproduced and repaired in a separate focused change. Its integration example is in `tests/disabled_test_FBDR/scripts/FBDSP.Rev`, i.e. currently disabled. Also review keep/restore chaining cpp:701–710 and touched-index treatment :713–743 before inheriting its caches.

## Revised integration routes

1. Preferred scientific target: species-identity-aware marginal DD likelihood on an oriented extended species tree, reusing the Taxon occurrence interface and explicit species lifetimes, with fresh global dynamic programming. Keep the hidden lineage count, plus sufficient identity/continuation state for reconstructed branches, distinguishing stretches on which a named species must persist from stretches before first observed identity is established. Derive the state-space closure from the 2018 q/qtilde likelihood. Do not assume the anonymous OBDP state (k,h) is sufficient or retain its 2k hidden-birth multiplicity on species-identity-constrained segments. Named species records demand compatibility with one continuous identity; an event factor omega*N alone loses that constraint.
2. Reliable prototype/reference: explicit complete species-tree or species-event-history augmentation, including entirely unseen species. Given that full history, total N(t) is known; demographic density is integrated total hazard N(t)[lambda(N(t))+mu] with birth/death events carrying the appropriate labeled-history rates, plus per-species fossil point-process likelihood on its lifespan and extant sampling. This is conceptually straightforward but requires transdimensional MCMC that jointly respects known species/parentage and occult species histories. It can be developed as a reference likelihood/simulator first, not presented as a finished scalable inference engine. Validate marginal DP against tiny enumerated histories or augmented simulation.
3. Existing FBDSP extended-tree representation is a useful compatibility target but full trait coupling needs an explicit observation-tree mapping. Fossil character states are observed at specimen ages, whereas extended tips are extinction ages. Passing extended species tree directly into dnPhyloCTMC attaches characters at the wrong times unless a separate species-level character model is explicitly defined. Add a deterministic map that inserts character-bearing specimen nodes on their species lineage and suppresses unobserved endpoints, or implement serial observations in the character likelihood. Multiple fossil specimens of one species are repeated lineage observations, not duplicate independent species. Extant molecular observations remain age zero.

Proposed named-data components: `SpeciesOccurrenceData` retaining specimen IDs (adapter from existing Taxon maps); `OrientedSpeciesHistory`/stable species-to-edge map; a deterministic `SpeciesObservationTreeFunction`; and the new DD distribution/kernel from the original plan. Reuse TimeTree only if child-order identity, stable tip index mappings, output/checkpoint round trips, and moves are demonstrably preserved. Otherwise an explicit history value with a derived TimeTree is safer. Topology/orientation, origination/extinction, occurrence-age, and parameter moves each need validity checks and reversible bookkeeping. A left/right child swap now changes which species survives a split and must be a genuine identity proposal, not an innocuous formatting operation.

Validation additions: repeated named occurrences cannot cross species origin/extinction; all occurrences of a species follow one identity path; named-vs-anonymous marginalization identities on tiny cases; budding continuation orientation proposals; full-occurrence versus range ascertainment; character observation-tree ages and repeated-specimen likelihood; alpha=0 comparison to analytically derived 2018 equations after FBDSP dispatch repair; zero lambda_a rejection of anagenetic structures; stochastic occurrence-age moves and endpoint moves restore all dependent trees and densities.
